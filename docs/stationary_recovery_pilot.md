# 换向恢复：只在目标静止时回退系数

这是[跨方向回归](reversal_recovery_transfer.md)失败后的单因素开发试验。
已有结果和噪声种子都公开，不是新盲测。默认固定 6 N 不变。

## 假设与改动

[逐拍诊断](tutorial/labs/03_reversal_recovery.md#7-继续诊断补偿力偏小应该先改哪个环节)发现，
旧候选在 5.308 s 的减速后段就开始回退，目标保持段却从 5.5 s 才开始。
本试验检验：延后到目标切向静止再回退，能否减少高负载重新启动代价，同时保留降载恢复收益。

新规则只把回退条件从目标切向速度小于 0.005 m/s 改为小于等于 $10^{-12}$ m/s。
后者用于识别数值零，不是搜索得到的新物理速度阈值。控制器不读取仿真时间或阶段标签，
也不要求实际末端速度已经归零。实测接触、可用测量包和未缩放投影等原门控仍然成立才回退。

原 `min_update_speed` 不变，因为它还控制运动确认和预算学习。预算仍为 6–8 N，
请求限速 20 N/s、系数限速 0.3/s、运动确认 50 ms，速度误差时间系数 0.05 s。
变化在[候选实现](../tools/stationary_recovery/controller.py)，原候选文件保持冻结。

## 运行前固定的范围

| 项目 | 取值 |
|---|---|
| 表面与误差 | −15°，无额外误差 |
| 摩擦 | 4–6 s 从 0.65 降到 0.30；或恒定 0.65 |
| 配对种子 | 11、29 |
| 新执行 | 静止回退候选，共 4 条 |
| 原位引用 | 原调度和旧回退候选各 4 条，共 8 条，不复制为新数据 |
| 总评价 | 12 条轨迹、两个物理场景 |

先按原门槛比较新候选与原调度：降载 8–10 s、8–12 s 的位置 RMSE 各下降至少 10%，
其余窗口位置增量不超过 0.1 mm，各窗口速度误差增量不超过 0.5 mm/s。
法向力、姿态和全程峰值的相对门槛以及绝对工程检查全部保留。
还要求高负载两个种子的 7–8 s 位置与速度误差 RMSE 都严格低于旧回退候选。
任一配对失败就不能通过这轮 pilot，不用平均值覆盖。

新候选与原调度在 5.5 s 前的所有逐拍字段须逐字节一致。该条件验证两者在本应改变之前
是否一致，也能暴露引用轨迹和当前执行环境的数值差异；失败后不通过放宽容差挽救结论。
脚本保存协议、源码哈希和原始轨迹，重算辅助状态方程。它不独立重算完整名义控制器或动力学。

## 复现

使用[固定环境](reproducible_environment.md)，在仓库根目录运行：

```bash
MUJOCO_GL=disable python -m tools.stationary_recovery.study \
  --output /tmp/stationary-recovery-pilot
```

目标目录必须不存在。源码必须已提交，运行前检查实际 BLAS 内核。
失败保留暂存轨迹，不覆盖旧归档，也不自动换参数补跑。
源码中的 `protocol_document()` 是本试验协议入口；归档中的 `protocol.json` 是运行时快照。
