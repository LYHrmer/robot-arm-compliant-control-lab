# 测量误差下，负载调度还能保留多少收益

27 次配对仿真已完成。沿用原门槛的 8 个组合误差检查通过 7 个，辅助力幅值低估 20% 时失败。
短时缺包和陈旧包能按既定规则回退并恢复；这不能代替传感器的幅值标定。
默认仍为固定 6 N、姿态增益 1、速度误差时间系数 0.05 s，不扩大负载调度预设的采用范围。

完整数字在[逐运行与配对结果](../results/franka_measured_budget_robustness/comparison.json)，
每次运行都附完整的 88 字段轨迹。原先的[60 条候选回归](load_budget.md#完整回归与推广决定)
保留原结论和精简轨迹，不用这一轮覆盖它。

## 比较是怎样固定的

运行前的[协议](../results/franka_measured_budget_robustness/protocol.json)固定了 9 种场景，
每种都运行调度 6–8 N、固定 6 N、固定 8 N。使用 seed 11、12 秒任务、500 Hz 控制，
属于公开开发实验，没有新盲测，也不把重复运行当成独立样本。

| 场景 | 固定的变化 |
|---|---|
| yaw 0° 组合误差，正常测量 | 原有测量流 |
| 同一物理工况，正／负偏置 | 6–12 s，沿目标切向运动方向加入 ±0.75 N |
| 同一物理工况，比例误差 | 6–12 s，辅助力的切向分量乘 0.8 或 1.2 |
| 同一物理工况，缺包 | 8.0–8.3 s 不提供辅助包，随后恢复 |
| 同一物理工况，陈旧包 | 8.0–8.3 s 重复最后一个旧包，过期后拒收，随后恢复 |
| yaw +15° 组合误差 | 正常测量，检查另一表面方向 |
| yaw 0°，负载下降与停止／换向 | 摩擦系数 0.65 保持到 4 s，4–6 s 线性降到 0.30；保留原制动、保持和反向轨迹 |

误差只加在调度器的辅助负载输入上，原法向控制反馈保持不变。陈旧包在包龄不超过 20 ms
时仍可用；本例接受 9 拍重复包，随后拒收 141 拍。缺包场景共拒收 150 拍。
它们都不等于整个 F/T 传感器断开，不能据此声称断开传感器后仍可控力。

## 位置误差与没有通过的检查

下表都是 yaw 0° 组合误差的 8–12 s 切向 RMSE。固定控制组的结果在所有辅助测量故障下
完全相同：固定 6 N 为 3.263 mm，固定 8 N 为 1.223 mm。

| 辅助测量 | 调度预算 RMSE [mm] | 原采用门槛 |
|---|---:|---|
| 正常 | 1.469 | PASS |
| +0.75 N 偏置 | 1.223 | PASS |
| −0.75 N 偏置 | 2.280 | PASS |
| 幅值 ×0.8 | 3.010 | FAIL |
| 幅值 ×1.2 | 1.223 | PASS |
| 缺包后恢复 | 1.595 | PASS |
| 陈旧包后恢复 | 1.591 | PASS |

×0.8 场景的后段改善只有 7.735%，低于原 20% 要求；8–12 s 的 3.010 mm 和
10–12 s 的 3.607 mm 也都超过 3 mm 门槛。三个失败项原样保留。低估负载使调度器开放的预算
不足，已有误差驱动系数仍受该预算约束；本轮没有用调参补偿这个标定误差。

yaw +15° 的正常测量配对通过，调度预算后段 RMSE 为 1.581 mm。这是第 8 个组合误差检查。
正偏置和幅值放大的成绩接近固定 8 N，不能解释为偏置有益；它们在此工况下更早用足预算，
没有证明普通工况也值得提高预算。

负载下降与停止／换向是另一个预先声明的工况，没有要求强行比低摩擦下的固定 6 N 再改善
20%。其 8–12 s RMSE 为调度预算 **1.375 mm**、固定 6 N **0.922 mm**、固定 8 N
**1.010 mm**。10–12 s 三者分别为 0.801、0.796、0.797 mm。调度预算在刚恢复运动时有代价，
不能只用后两秒的接近结果掩盖它。

所有 27 次运行均通过原有的五项绝对工程门槛：接触比例最低 100%，完整轨迹接触力峰值
最高 12.638 N，力矩裁剪和投影均为 0%，最小保留力矩余量为 4.422 Nm。
18 个配对的力／姿态／峰值代价检查也通过。位置与速度的逐阶段差值仍单独列在结果中；
工程门槛通过不表示每项跟踪性能都更好，更不是真机安全认证。

## 如何确认故障和状态更新确实发生

本轮独立回放全部 162,000 拍，使用记录的测得位置和速度重建运动确认、在线系数与预算。
最大系数误差约 `4.44e-16`，补偿请求误差约 `6.22e-15 N`。缺包和陈旧包场景各有 5 拍
输出高于刚下降的目标预算，但仍满足全局 8 N 和有效接触周期内的 20 N/s 约束。
为什么不能把这几拍直接判成超限，见[逐拍回放练习](tutorial/07_measured_budget_replay.md)。

误差发生前的 18 组配对前缀逐字段完全相同。固定控制组另外核对了整条 12 秒轨迹：每档预算
下的六类故障均不改变运动、法向反馈和力矩输出，确认辅助故障没有进入其他反馈通道。
原始辅助包和实际送入调度器的包分别存储，验收会从原测量重建声明的偏置／比例变换，
不会只相信记录的 `load_packet_status`。

报告生成期间修正过两处实现问题：新增七阶段工况不能套用旧三阶段名称，顶层状态也必须计入
已声明的力矩投影和余量门槛。第一次的 27 条原始轨迹保留在开发机上；修正后按相同协议复跑，
全部 2,376 个数组逐值一致。归档只计 27 次实验，不计成 54 个样本。控制器与门槛没有改动。

安装项目依赖后，在仓库根目录只读核对已发布结果：

```bash
python -m tools.measured_budget_robustness audit results/franka_measured_budget_robustness
pytest tests/test_measured_budget_archive.py tests/test_measured_budget_robustness_reporting.py -q
```

`observed_status: PASS` 表示绝对工程检查通过，采用检查的 `scale_0p8` 仍为 `FAIL`；
`eligible_for_default_change` 为 `false`。完整配对信息以 `comparison.json` 为准。

重新运行需要一个不存在的目录，不覆盖已发布归档：

```bash
python -m tools.measured_budget_robustness run /tmp/compliant-control-measured-robustness-01
```
