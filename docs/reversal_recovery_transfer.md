# 换向恢复：跨方向与组合误差回归

这一轮不调整控制器，检查[停顿系数回退候选](reversal_recovery.md)能否保留已有收益，
以及高负载重新启动的代价会不会扩大。对照始终是原 6–8 N 调度方法，
不是默认固定 6 N，也不是 BC/PPO。

结果为 **34/36，通过范围不足，整体 `FAIL`**。降载恢复的收益跨方向保留；
但 −15° 无额外误差的高负载反例，两次噪声重复都超过反向加速代价门槛。
不扩大候选的采用范围，默认仍为固定 6 N、姿态增益 1、速度误差时间系数 0.05 s。

## 比较范围

[协议](../tools/reversal_recovery_transfer/protocol.json)在新仿真执行前固定。
所有运行使用 12 s 停止／换向轨迹、2 ms 步长、姿态增益 1 和速度误差时间系数 0.05 s。

| 维度 | 取值 |
|---|---|
| 真实表面方向 | −15°、0°、+15° |
| 负载变化 | 摩擦在 4–6 s 从 0.65 降至 0.30；或一直保持 0.65 |
| 输入误差 | 无额外误差、组合误差、组合误差加辅助切向力幅值 ×0.8 |
| 测量噪声种子 | 11、29 |
| 方法 | 原调度、同一个停顿系数回退候选 |

组合误差包含两项：控制器法向估计偏转 +3°；从 6 s 起，原始 wrench 反馈增加
沿真实表面法向的 0.75 N 偏置。换表面方向时，这个偏置也旋转到对应的世界坐标方向。
第三种设置在此基础上，将 6–12 s 的辅助切向力测量乘以 0.8；它不缩放主法向力反馈。

这形成 36 个配对、72 条轨迹。0° 无额外误差的 8 条轨迹直接引用上一轮归档，
新增 64 次仿真。三种方向与两种负载共 6 个物理设置；再加三种输入误差得到 18 个设置。
噪声种子和两种控制器都不增加独立物理场景的数量。

沿用相同种子是为了做配对比较。两次噪声重复不足以支持统计显著性或普遍鲁棒性结论。
本轮不覆盖缺包、过期包、幅值高估、新质量组合或 pitch/roll 变化。

## 什么算通过

不对多方向或多种子取平均后验收。每个配对都按上一轮的门槛判断：

| 检查 | 门槛 |
|---|---|
| 降载后的恢复收益 | 8–10 s、8–12 s 的切向位置 RMSE 各降低至少 10% |
| 其他窗口的位置代价 | 最多增加 0.1 mm |
| 各比较窗口的速度代价 | 速度误差 RMSE 最多增加 0.5 mm/s |
| 每阶段法向力与姿态代价 | RMSE 增量分别不超过 0.2 N、0.1° |
| 完整轨迹峰值代价 | 未滤波接触力峰值最多增加 1 N |

两种方法还都须满足原绝对工程检查：接触比例至少 99%、峰值不超过 35 N、
执行器裁剪与力矩投影比例为零、最小预留力矩余量至少 1 Nm。
切向误差指标使用真实表面的切平面，控制器的 +3° 法向偏差只进入控制过程。

报告把失败分开列出：`missed_benefit_checks` 表示未达到预定收益；
`paired_cost_failures` 表示相对代价超限；`absolute_failures` 表示绝对工程检查未过。
前一种失败不等于发生了接触或力矩越界。反过来，绝对工程检查通过也不能代替恢复收益。

## 结果

[完整比较](../results/franka_reversal_recovery_transfer/comparison.json)保存全部 72 条评价。
降载场景 **18/18** 通过，高负载反例 **16/18** 通过。下表每格是两个噪声种子的通过数，
不是对两个种子平均后判断。

| 真实表面方向 | 输入误差 | 降载 | 恒定高负载 |
|---|---|---:|---:|
| −15° | 无额外误差 | 2/2 | 0/2 |
| −15° | 组合误差 | 2/2 | 2/2 |
| −15° | 组合误差＋辅助幅值 ×0.8 | 2/2 | 2/2 |
| 0° | 无额外误差（引用旧轨迹） | 2/2 | 2/2 |
| 0° | 组合误差 | 2/2 | 2/2 |
| 0° | 组合误差＋辅助幅值 ×0.8 | 2/2 | 2/2 |
| +15° | 无额外误差 | 2/2 | 2/2 |
| +15° | 组合误差 | 2/2 | 2/2 |
| +15° | 组合误差＋辅助幅值 ×0.8 | 2/2 | 2/2 |

18 个降载配对中，8–10 s 位置 RMSE 降低 27.64%–40.69%，8–12 s 降低
18.68%–32.89%，均超过各自的 10% 门槛。但恢复末段并非每项都变好：
10–12 s 速度误差 RMSE 在这 18 对中均略增，增量为 0.008–0.026 mm/s。

### 两条失败在哪里

两条都是 −15°、无额外误差、摩擦恒定 0.65 的 7–8 s 反向加速段。
下表箭头是原调度 → 候选，增量用未舍入指标相减。

| seed | 位置 RMSE [mm] | 位置增量 [mm] | 速度误差 RMSE [mm/s] | 速度增量 [mm/s] |
|---:|---:|---:|---:|---:|
| 11 | 1.659 → 1.772 | +0.113319 | 3.738 → 4.282 | +0.544698 |
| 29 | 1.643 → 1.755 | +0.111824 | 3.692 → 4.261 | +0.569248 |

它们分别超过 +0.1 mm 和 +0.5 mm/s 的原门槛。因此失败字段都是
`ramp:position_cost` 与 `ramp:velocity_cost`。不是恢复收益不足，也不是绝对工程检查失败。
所有高负载配对的加速位置误差都有增加，只是在其余 16 对中未超过门槛。

72 条轨迹的接触比例均为 100%，最大原始接触力峰值 12.647 N，执行器裁剪和力矩投影
比例均为零，最小预留力矩余量 3.983 Nm。全部阶段的最大法向力 RMSE 增量 0.012665 N，
最大姿态 RMSE 增量 0.009955°，也未越过相对门槛。这些仍只是仿真工程检查。

### 可以得出什么结论

可以保留“该局部规则改善了本批降载后的换向恢复”，不能改写成“已经全面修复换向”。
失败与高负载下回退补偿可能拖慢再启动的反例假设相符；为什么 −15° 更敏感，仍需单独诊断。
本轮不据结果调整回退速率、改控制器或放宽代价门槛。

幅值 ×0.8 的组通过，也不表示[原测量回归的失败](measured_budget_robustness.md)已解决：
这里比较候选与原调度，那里包含对固定 6 N 的采用检查。两次实验的对照和场景不同，
不能用本轮的通过数覆盖原来的 7/8。组合误差组通过也不证明人为加入误差能改善控制。

本轮仍未验证候选在原 public24 质量／姿态网格中的兼容性，未完成候选的 C++ 移植，
更不提供真机、稳定性或被动性保证。

### 数据是否完整

64 次新仿真各执行一次，与原 8 条引用轨迹合计 432,000 拍。36 个候选配对在 4.5 s 前、
24 个误差配对在 6 s 前的所有 69 个逐拍字段均逐字节一致，共 60 项前缀检查通过。
逐拍辅助状态和测量来源校验通过；换用另一 CPU 数值内核复算，仍得到相同的 `FAIL` 判定。

执行前冻结提交为 `03cd2a53d88871e9805712a123b7ce45be422ad4`；
[manifest](../results/franka_reversal_recovery_transfer/manifest.json)和
[源码哈希](../results/franka_reversal_recovery_transfer/source_hashes.json)记录实际输入。
8 条引用数据保持原路径及原哈希，未复制成“新实验”。

## 如何复核

使用[固定环境](reproducible_environment.md)，在仓库根目录运行：

```bash
MUJOCO_GL=disable python -m tools.reversal_recovery_transfer.study \
  --audit results/franka_reversal_recovery_transfer
```

`archive_integrity` 检查归档哈希、来源及逐拍状态重算；`comparison_status`
报告性能门槛结果。这两个状态可以分别是 `PASS` 和 `FAIL`。
保留下来的有效失败实验不应为了显示绿色而重新命名。

重新执行时使用一个尚不存在的新目录，不覆盖已发布结果：

```bash
MUJOCO_GL=disable OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
  python -m tools.reversal_recovery_transfer.study \
  --output /tmp/compliant-control-recovery-transfer
```

复核会重算辅助通道的系数、预算、运动确认与请求限速，也核对测量包的误差注入来源。
它不重新积分动力学，不独立重算完整名义控制器，更不构成真机安全保证。

源码、产物哈希和配置严格相同。逐拍前缀按形状、数据类型与字节比较，包含正负零的区别。
连续指标摘要复算的绝对容差为 $10^{-10}$，审计误差摘要为 $10^{-12}$，相对容差为零。
这些容差在运行前写入协议，用来容纳 CPU 数值内核的末位差异；计数、状态、失败原因和
采用门槛不适用这个容差，仍严格核对。

先读[带答案的换向故障实验](tutorial/labs/03_reversal_recovery.md)，再看本轮结果，
可以检查一个在单方向有效的局部修正规则，是否值得扩大使用范围。
