# v0.6 开发实验：接近参考与采样时序

这一轮先处理两个基础问题：目标位置与速度的关系，以及控制器在每个周期究竟读到了哪一刻
的数据。新增参考治理器只约束参考运动，不承诺实际末端速度或接触力一定满足限制。

v0.5 的控制器默认值和冻结档案保留不动。这里使用已公开的 48 个场景进行开发对照，
不计作新的未见数据实验；Residual RL 和表面法向估计尚未加入这一轮。

## 先看四组分别改了什么

| 组名 | 仿真时序 | 接近参考 | 用途 |
|---|---|---|---|
| `legacy_replay` | 旧模式 | 原始位置轨迹，目标 x 速度为零 | 核对 v0.5 的 7 项确定性指标 |
| `timing_only` | 分步模式 | 保留原始参考 | 新时序下的比较基线 |
| `consistent_reference` | 分步模式 | 速度取位置轨迹的解析导数 | 单独检查速度参考的影响 |
| `rate_limited_reference` | 分步模式 | 有状态的位置参考与离散速度 | 检查参考限速、制动的收益及代价 |

四组使用相同的逐场景噪声种子，任务时长也相同。后三组应互相比较；旧模式与新模式之间的
差异含有仿真时序变化，不能全部记到控制器改进上。后三组仍沿世界 x 方向控力。
单独检查治理器的效果时，比较 `rate_limited_reference` 与 `consistent_reference`；
生成摘要中的统一比较对象为 `timing_only`，需要区分这两个问题。

## 这次跑出了什么

完整运行包含 192 次仿真。旧模式的 48 个场景与 v0.5 档案逐项一致，7 项确定性指标的最大
绝对误差为 0。下面只比较同一分步时序下的三个方案：

| 指标 | 原始参考 | 解析速度参考 | 有状态限速参考 |
|---|---:|---:|---:|
| 全部门槛通过数 | 23/48 | 24/48 | 23/48 |
| 全轨迹 raw peak P95 [N] | 60.89 | 59.03 | 61.63 |
| 至少一次超过 35 N 的场景数 | 20/48 | 18/48 | 19/48 |
| 首次接触时间中位数 [s] | 0.569 | 0.511 | 0.565 |
| 后期 raw peak P95 [N] | 44.16 | 43.70 | 42.25 |
| Force RMSE P95 [N] | 2.346 | 2.339 | 2.356 |

所有方案的 48 个场景都建立了接触，任务评价窗口内的接触率均为 100%，执行器饱和率均为 0%。
补上速度参考后，配对接触时间差的中位数为 −0.030 s，全轨迹峰值差的中位数为 −0.438 N。
它在这批公开数据上有小幅改善，距离 35 N 峰值门槛仍很远。

有状态限速参考的后期峰值 P95 较低，但全轨迹峰值 P95 更高，通过数没有增加。当前保留为
实验选项，不替换主基线，也不据此宣布“低冲击控制已完成”。后续优先检查表面坐标误差与
接近段实际动力学；新的性能主张仍需独立未见数据。

相对解析速度组，加入治理器后，配对全轨迹峰值差的中位数为 +0.275 N，首次接触延迟差的
中位数为 +0.054 s。摘要中的超限时间中位数为零，只表示至少一半场景没有超限，不能解释为
所有场景均满足 35 N 限制。

## 位置在变，为什么速度不能随便填零

原始接近段在 0.10–1.00 s 使用 smoothstep：

$$
s=\operatorname{clip}((t-0.10)/0.90,0,1),\quad h(s)=3s^2-2s^3,
$$

$$
p_d=p_0+h(s)(p_c-p_0),\qquad
\dot p_d=\frac{6s(1-s)}{0.90}(p_c-p_0).
$$

区间外接近速度为零。新选项 `approach_reference="consistent"` 补上这个导数，保持位置
轨迹和目标力不变。测试用位置的中心差分核对速度，也检查两个端点。

零目标速度本身可以表达一种阻尼设计，但它与“跟踪运动轨迹的速度参考”含义不同。接近控制中
的阻尼项包含 `D * (v_d - v)`。补上正向 `v_d` 会增加正向驱动力，首次接触甚至可能提前。
是否减小冲击，要看接触时的实际速度和力峰值，不能只看公式是否一致。

擦拭轨迹暂时沿用旧实现。1.20 s 开始擦拭时的切向速度切换仍然存在；本轮没有把整条任务
轨迹改成连续加速度轨迹。

源码：[目标生成与仿真](../src/compliant_control_lab/franka_simulation.py)。
验证：[导数与时序测试](../tests/test_franka_timing.py)。

## 每个周期的数据来自哪里

默认 `control_timing="legacy"` 保留历史计算顺序。在这一模式中，缓存的位置和雅可比来自
前一次前向计算，关节速度却已经积分更新，旧日志只能按控制周期解释。

`control_timing="split_step"` 使用以下顺序，`k` 表示当前周期：

```text
mj_step1：更新 x[k]、J[k] 和 bias
    ↓
读取已缓存的 F[k-1]，滤波，再施加场景规定的观测延迟
    ↓
控制器计算 u[k]，写入关节力矩
    ↓
mj_step2：求解 F[k] = F(x[k], u[k])，随后积分到 x[k+1]
    ↓
立即缓存 F[k]，供下一周期反馈
```

接触约束力在 `mj_step2` 中求解。虽然读取它时 `data.time` 已经前进，力仍对应积分前的
状态与本周期指令。下次 `mj_step1` 会重建接触索引，所以缓存的是已经求出的标量力，
不能在索引更新后重新读取上周期接触。[MuJoCo 官方仿真循环说明](https://mujoco.readthedocs.io/en/latest/programming/simulation.html)

分步模式下，一行中的实际位置、速度与 raw force 均标记为 `time[k]`。控制器得到的力反馈
来自上一周期，另有滤波滞后和场景配置的观测延迟。`measured_force_sample_time` 标记滤波器
最新原始输入的时间，`measured_normal_force` 记录加入延迟、偏置及噪声后的实际控制器输入。
启动阶段重复使用时间为零的初始化观测，没有虚构负时间的力样本。

当前模型使用 `implicitfast`。分步模式拒绝 RK4，防止 MuJoCo 静默改用其他积分器。
若仿真自动重置导致时间不连续，实验也会终止，不会继续输出看似连续的时间戳。

## 有状态参考怎么计算

治理器维护法向参考位置 `p_r` 和速度 `v_r`，重置时取实测位置、零参考速度。每次调用先确定
一个位置目标：不超过任务目标，也不超过实测位置前方 10 mm。随后根据剩余距离计算减速速度。

默认参考速度上限为 0.025 m/s，加速度上限为 0.10 m/s²。每周期更新满足：

$$
|v_{r,k+1}|\leq v_{max},\qquad
|v_{r,k+1}-v_{r,k}|\leq a_{max}\Delta t,
$$

$$
p_{r,k+1}=p_{r,k}+\Delta t\,v_{r,k+1}.
$$

本周期把更新后的 `p_r` 和 `v_r` 一起交给自适应控制器。实测正向速度超过限值时，治理器
要求参考停止继续加速前进，仍按加速度约束制动。力冲击守卫使用前一周期的估计，同样调整
位置目标，不瞬间跳变参考位置。

10 mm 在这里是位置目标的限制。若传感器位置跳变，或任务突然要求后退，参考制动期间可以
暂时超过这个距离；强行把位置截断会破坏上面的离散导数关系。力矩投影仍由原自适应包装层执行。
这些规则没有给出实际机器人速度的硬上界，也没有无源性证明。

实现与测试：[参考治理器](../src/compliant_control_lab/franka_reference.py)、
[长序列、反向运动和重置测试](../tests/test_franka_reference.py)。

## 自己运行

按[环境说明](tutorial/README.md#环境与第一轮复现)安装项目后，在仓库根目录运行：

```bash
python -m compliant_control_lab.reference_ablation --output /tmp/franka-reference-full
```

先核对全部冻结档案，再重放四组各 48 次。`legacy_replay` 的任何一项确定性指标与冻结值相差
超过 `1e-12`，都会停止后续实验。`controller_p95_us` 受机器负载影响，不参与这个核对。
本次复现环境为 Python 3.10.12、NumPy 2.2.6、MuJoCo 3.12.0。其他依赖版本或平台若产生
数值漂移，程序会报错，不会把不一致的旧模式结果继续标成已验证。

只想检查命令是否能跑通，可以先做一个场景：

```bash
python -m compliant_control_lab.reference_ablation \
  --case-indices 0 --output /tmp/franka-reference-one
```

输出目录必须不存在或为空。程序拒绝冻结目录及其父目录，也拒绝经过符号链接的输出路径。
完成后才发布包含 `comparison.csv` 和 `manifest.json` 的报告；manifest 保存实际参数和
源码、模型文件的哈希。复跑应使用新目录，不能覆盖先前结果。

读结果时先看接触建立时间及接触率，再比较首次接触后 0.5 s 内的峰值与 1.0 s 以后的峰值。
0.5–1.0 s 的过渡窗口仍计入全轨迹峰值。没有接触或没有观测到指定窗口时，诊断值为 `NA`。
墙面真实法向仅用于投影诊断数据，没有作为控制器额外输入。

## 先算一遍，再运行

取接近刚度 800 N/m、阻尼 120 N·s/m，目标位置在实测位置前方 0.010 m，实测法向速度
为 0.020 m/s。接近命令为 `F = K * e + D * (v_d - v)`。

| 目标速度 | 位置项 | 阻尼项 | 接近力命令 |
|---|---:|---:|---:|
| 0 m/s | 8 N | −2.4 N | 5.6 N |
| 0.025 m/s | 8 N | +0.6 N | 8.6 N |

两组都没有触发 12 N 的接近命令上限。改变目标速度后，阻尼项由负转正，总命令仍然朝向
墙面，但增大了 3 N。机械臂可能更早接触，冲击峰值却不一定降低。这里算的是接近力命令，
还没有经过接触过渡和完整控制链；它不等于传感器测得的接触力。

先预测 `timing_only` 与 `consistent_reference` 的接触时间差，再运行单场景命令检查。
解析速度随时间变化，上表的 0.025 m/s 只是一帧示例，不能替代整条轨迹。比较首次接触后
0.5 s 内的未滤波峰值，同时检查接触率；场景、噪声 seed 和任务时长都要保持相同。
最后加入限速参考，看看参考约束成立时，接触表现是否真的更好。

本节数值练习由 Claude 辅助起草，单位与力的方向表述已核对修订。
