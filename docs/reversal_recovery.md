# 换向恢复：停顿期间的系数回退

这轮只检查降载、停顿之后的换向恢复。固定 6 N 仍是默认配置；可选 6–8 N 调度、
旧回归和 C++ 实现不作修改。BC/PPO 与六轴项目不参加这轮比较。

## 从哪一个现象开始

[已有降载实验](measured_budget_robustness.md)中，摩擦系数在 4–6 s 从 0.65 降至 0.30，
5.5–7 s 停顿，7–8 s 反向加速。调度方法在 8–12 s 的切向 RMSE 为 1.375 mm，
固定 6 N 为 0.922 mm；只看最后两秒，两者又接近 0.8 mm。
平均误差掩盖了恢复初段的差异。

最初怀疑停顿时预算没有及时下降，但原始轨迹不支持这个解释：

| 7.000 s 的状态 | 测得负载调度 | 固定 6 N |
|---|---:|---:|
| 当前预算 | 6.000 N | 6.000 N |
| 切向补偿请求模长 | 0 N | 0 N |
| 下一次运动会使用的等效系数 | 0.616769 | 0.488322 |

调度器保留的负载估计为 5.316816 N，加上 0.25 N 余量仍低于 6 N 下限。
单独衰减这个估计，不会降低当前预算。需要检查的是：预算下降后，之前积累的系数
仍可能高于当前力预算所允许的幅值，停顿期间也不会按原运动更新律释放。
该系数由误差驱动，并非辨识出的材料摩擦系数。

这些是轨迹中的状态差异，还不能单独证明因果。运动确认、输出向量限速和后续闭环误差
也会影响恢复；本轮保持它们不变，只试下面一个候选。

## 唯一候选改了什么

在原 `advance()` 之后，只有接触有效、辅助测量包可用、力矩投影接受原请求、目标切向速度
低于原更新阈值，且修正法向力大于 1 N 时，才释放高于当前预算的系数：

$$
\mu_{\mathrm{cap}} = \min\left(\mu,\frac{B_k}{F_{n,k}}\right),\qquad
\mu_{k+1}=\max\left(\mu_{\mathrm{cap}},\mu-\dot{\mu}_{\max}\Delta t\right).
$$

其中 $B_k$ 是本拍使用的预算，$F_{n,k}$ 是控制器修正后的法向力。
沿用原系数变化率上限 $\dot{\mu}_{\max}=0.3\ \mathrm{s}^{-1}$；2 ms 一拍最多下降 0.0006。
本拍输出不重算，下一拍才使用新系数。系数没有被清零，也没有被强制设回名义值。
移动时仍使用原误差更新律；20 N/s 输出向量限速、运动确认与力矩投影全部保留。

高负载下预算可能本来就允许较大的系数。此时该规则不应无条件清掉已有补偿，
但是否影响重新起动仍要通过闭环对照检查，不能只用这一拍公式判断。

## 先固定比较范围

[协议](../tools/reversal_recovery/protocol.json)在新仿真运行前写入，哈希为
`f1052d68d0458ad9308f6326bac60235d4be25c4e196082e01066c43fe35667c`。

| 项目 | 预定范围 |
|---|---|
| 物理场景 | 原降载停顿／换向；相同轨迹但摩擦保持 0.65 的高负载反例 |
| 随机种子 | 每个场景 11、29；两个种子不算两个独立物理场景 |
| 方法 | 原 6–8 N 调度、增加停顿系数回退的候选 |
| 执行规模 | 4 个配对，8 次仿真，每次 12 s、500 Hz |
| 其余参数 | 表面方向 0°、姿态增益 1、速度误差时间系数 0.05 s，辅助包正常 |

降载场景的两个种子都须在 8–10 s 和 8–12 s 改善至少 10%。其他位置误差窗口最多增加
0.1 mm，所有比较窗口的速度 RMSE 最多增加 0.5 mm/s。法向力、姿态、完整轨迹峰值与
原绝对工程门槛继续检查；完整门槛见协议，不按结果修改。

即使全部通过，也只说明值得进入更广的公开回归。这不是新盲测，不足以更改默认值，
也不覆盖跨表面方向、测量比例误差、C++ 移植或真机验证。

## 新的闭环对照

[完整结果](../results/franka_reversal_recovery/comparison.json)保留 8 次仿真、48,000 拍，
4 个配对均通过预定门槛。下面比较的是原 6–8 N 调度与候选，不是与默认固定 6 N 的新比较。

| 降载场景 | 8–10 s 切向 RMSE，原方法 → 候选 | 8–12 s 切向 RMSE，原方法 → 候选 |
|---|---:|---:|
| seed 11 | 1.771 → 1.051 mm（改善 40.7%） | 1.375 → 0.932 mm（改善 32.2%） |
| seed 29 | 1.774 → 1.052 mm（改善 40.7%） | 1.378 → 0.936 mm（改善 32.1%） |

降载的 8–10 s 速度误差 RMSE 也从 1.949 / 1.962 降至 0.926 / 0.950 mm/s。
不过，7–8 s 的速度误差仍稍有增加；改善恢复初段不等于每个窗口都改善。

高负载反例没有零代价通过：seed 11 / 29 在 7–8 s 的位置 RMSE 分别增加
0.074 / 0.079 mm，速度 RMSE 增加 0.375 / 0.415 mm/s。它们小于预定的
0.1 mm / 0.5 mm/s 上限，但最差速度增量距离门槛仅约 0.085 mm/s。
这批结果支持继续做换向恢复回归，不支持直接推广，也没有解决辅助力幅值低估的问题。

每个配对在 4.5 s 前的 2,250 拍、69 个逐拍字段完全相同。候选在减速末段 5.308 s
首次释放系数，本拍的更新后状态已不同；到 5.310 s，下一拍才使用新系数。
目标速度低于更新阈值的条件也覆盖这一段，
并非只在严格零速时起作用。恢复运动确认仅提前 4–10 ms，不能把约 40.7% 的改善简单解释为
取消了运动确认。这是本批单变量仿真的机制证据，仍不证明对任意接触环境都有效。

8 次仿真的接触比例均为 100%，完整轨迹 raw peak 最大 12.637 N，无执行器裁剪或力矩投影，
最小预留力矩余量 4.070 Nm。这些是仿真工程检查，不是真机安全保证。

### 复算和重新运行

使用[固定 core 环境](reproducible_environment.md)，从仓库根目录运行：

```bash
python -m tools.reversal_recovery.study --audit results/franka_reversal_recovery
```

预期分别报告 `archive_integrity: PASS` 和 `comparison_status: PASS`，并保留
`default_changed: false`。前者指产物哈希、来源和状态重算一致，后者指这四对通过门槛。
它们不是两个独立实验，也不能代替真实机器人验证。

要重新做 8 次仿真，使用一个尚不存在的新目录：

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
  python -m tools.reversal_recovery.study --output /tmp/compliant-control-reversal-study
```

输出目录已存在时命令拒绝执行；不要覆盖已发布归档。审计独立重算补偿系数、请求限速、
运动确认、测得负载预算及对应指标，不重新积分动力学，也不声称独立重算完整名义控制器。
执行器上下文始终存在是本协议的前提，投影接受标志由合法的投影比例双向核验。

本批物理计算来自提交 `64176be`，原执行源码哈希保留在
[`source_hashes.json`](../results/franka_reversal_recovery/source_hashes.json)。首次归档收尾时，
JSON 的列表与内存中的元组被误判为不一致。修复只统一序列化比较和补充归档收尾入口，
没有重跑仿真、修改轨迹或改写原执行身份；审计仅对这一个已知工具版本提供明确兼容。
