# 按测得负载调节补偿预算

固定 8 N 可以减小高摩擦段的位置残差，但原 public24 兼容检查只有 23/48 通过。
这一轮尝试保留普通工况的 6 N 上限，仅在测得切向负载持续升高时开放额外预算。
这次 6 个组合误差候选和 12 个普通工况候选均通过小规模门槛，支持继续扩大原矩阵回归。
它还没有覆盖全部 48 组兼容条件。

默认控制器仍为 6 N、姿态增益 1、速度误差时间系数 0.05 s。
新方法位于 `tools/`，没有接入默认运行路径。

## 控制器实际能看到什么

原来的在线系数由位置误差和速度误差更新。这次额外使用六维力传感器的切向分量，
取自与当前法向力相同的延迟、滤波后的测量包。传感器使用 robot-on-environment
符号约定；沿目标运动方向的正投影表示需要克服的负载，无需取负号。

输入适配器只读取时间戳和 `measured_wrench_world`，转换到控制器坐标系后，核对其
法向分量是否等于原控制器收到的法向力。仿真中的真实摩擦系数和真实接触力不会进入调度器。
质量补偿误差会残留在力测量中，动态时还包括惯性项。传感器偏置也未被这一规则单独识别，
所以这里的“负载”不能解释为摩擦辨识结果。

这项比较增加了传感器输入，也改变了预算规则。它回答新配置是否实用，不能单独证明
增益调度本身优于旧更新律。

## 一拍内的顺序

令目标切向速度的单位方向为 $d_k$，测得的局部力为 $F_k$。
父控制器使用的平滑方向并非单位向量，不能直接拿来计算以 N 为单位的负载。

$$
\ell_k=\operatorname{clip}(F_k^\mathsf{T}d_k,0,8),\qquad
L_{k+1}=L_k+(1-e^{-\Delta t/0.20})(\ell_k-L_k),
$$
$$
b_{k+1}=\operatorname{clip}(L_{k+1}+0.25,6,8)\ \mathrm{N}.
$$

当前拍先用 $b_k$ 计算补偿力。原有系数更新检查当前拍是否已到上限，完成后才计算
下一拍的 $b_{k+1}$。只有接触有效、运动确认通过且力矩投影接受原请求时才更新负载。
因此 0.20 s 按有效更新周期累计，不能当作连续墙钟时间的响应常数。

缺少新的测量包时，负载估计清零、预算回到配置的最小值；不会仅因辅助测量缺失清空原系数。
接触丢失则同时重置两者。预算下降也保留 20 N/s 的力变化率限制，因此实际补偿力可在短时间内
高于新预算，但仍受全局 8 N 范数上限约束。不能在输出端突然裁剪来绕过这一过程。

代码从 [输入适配器](../tools/load_budget_inputs.py)进入
[补偿器](../tools/load_aware_compensation.py)，闭环调用见
[运行适配器](../tools/load_budget_trial.py)。这些边界均有测试。

## 先做多大实验

运行前固定的[协议](../tools/load_budget_protocol.json)要求：先精确复现两个固定 6 N
控制组，再运行三个表面方向、两档姿态增益的 6 个组合误差候选。
8–12 s 的切向 RMSE 要不超过 3 mm，并比同工况旧 6 N 至少降低 20%；10–12 s 也须
不超过 3 mm。接触比例、力与姿态代价、力矩余量沿用旧门槛。

只有这一步全部通过，才运行原 public24 中 case 6、7、14、15、22、23 的两档增益，
共 12 条候选轨迹。它们覆盖三个方向、两个原噪声种子，固定为原矩阵中的 0.13 kg、
0.012 s 工况。普通工况相对旧 6 N 的位置代价不能超过 0.10 mm，速度 RMS 代价不能
超过 0.0002 m/s。

这些都是已公开的开发工况。即使小规模检查通过，也只够支持扩大原矩阵回归，不能直接修改默认值。
本轮不训练 BC/PPO，也不重新解释历史 v0.5 的 FAIL。

## 已得到的结果

完整数值在 [comparison.json](../results/franka_load_budget_pilot/comparison.json)，
每个候选都与相同方向、相同姿态增益的旧 6 N 轨迹配对。

| 检查范围 | 旧 6 N | 按负载调节预算 | 判定 |
|---|---:|---:|---|
| 组合误差 8–12 s 切向 RMSE，6 对 | 3.255–3.333 mm | 1.465–1.581 mm | 6/6，通过；降低 52.4%–55.3% |
| 同一批候选 10–12 s 切向 RMSE | 门槛为 3 mm | 1.117–1.197 mm | 全部通过 |
| 普通工况位置、速度及力/姿态/峰值验收指标，12 对 | 原 6 N 轨迹 | 各项差值均为 0 | 12/12，通过 |

普通工况的位置追赶统计也与旧 6 N 相同。这一结果没有证明它比固定 8 N 追赶更快；
候选在这些普通工况中没有开放额外预算。三个方向的候选增益 2 减增益 1 代价检查也全部通过。

归档含 18 条候选轨迹和两个固定 6 N 控制组，共 71,250 个周期。两个控制组精确复现了原归档
字段；固定 6/6 N 与 8/8 N 的逐周期控制器等价性另由单元测试覆盖。独立验收从测量包重构
负载估计和补偿请求，最大数值误差小于 `2.7e-15 N`。

精简轨迹未保留完整的测得位置/速度，归档验收不重新推算每拍原系数更新，输出中的
`coefficient_transition_checked` 为 `false`。系数因果时序与当前上限 anti-windup 有单元测试，
但不能把这些测试写成对 71,250 拍原系数更新的逐拍验证。

开发时修正了 public 精简轨迹漏存 `contact_blend`、统计代码错误引用表面法向属性两处问题。
协议参数没有改动；确定性复跑不计作额外独立样本。

接下来按原协议补齐另外 36 条 public 候选，以及 6 条 `no_bias` 动态候选。
在这些结果出来前，原固定 8 N 的 23/48 和旧时间系数实验的 `do_not_expand` 都继续保留。

## 复现

在仓库根目录按项目环境说明安装依赖后，运行到一个不存在的输出目录：

```bash
PYTHONPATH=src:.local-deps:. python -m tools.load_budget_study run /tmp/load-budget-pilot
```

协议和源码哈希在仿真前写入。归档完成后，`audit` 只读取轨迹，重新计算控制检查与性能门槛：

```bash
PYTHONPATH=src:.local-deps:. python -m tools.load_budget_study audit results/franka_load_budget_pilot
```

位置追赶统计仅用于解释取舍，不是临时增加的采用标准。本轮也不承诺比固定 8 N 更快追上目标。
速度时间系数实验仍保留原来的 `do_not_expand`。
