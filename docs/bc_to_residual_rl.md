# BC 表示能否帮助残差 PPO

[输入消融](bc_closed_loop_transfer.md)已经改善了 BC 的闭环跟踪。本节记录后续的
表示迁移对照：把 BC 学到的隐藏层交给 PPO，但不沿用 BC 的输出动作。
训练方案在 BC 完成后单独冻结；初始化测试不能替代性能评价。

## 两种控制器的动作不能直接互换

BC 的基底是自适应导纳，教师标签提供额外摩擦补偿。PPO 的基底已经包含摩擦前馈。
同一个三轴数值，放在这两个基底上，会产生不同的总控制命令。

也不能简单计算“BC 输出减去摩擦前馈”：教师标签位于残差安全层之前，后面还有
接触门控、滤波和变化率限制，最后才做力矩投影。这些处理有内部状态，而且名义
控制器每秒更新 500 次，学习动作每秒只更新 50 次。逐项相减无法保证实际施加的力一致。

这次只改变 actor 的初始化。

| 部分 | 从零开始的 PPO | BC 隐藏层迁移 |
|---|---|---|
| 第一隐藏层，49 → 32 | 原始随机初始化 | 复制同种子 BC 的权重与偏置 |
| 第二隐藏层，32 → 32 | 原始随机初始化 | 复制同种子 BC 的权重与偏置 |
| 动作层，32 → 3 | 权重和偏置全零 | 权重和偏置全零，不复制 BC 动作层 |
| 价值网络 | 新的随机初始化 | 与从零开始版本使用相同种子的初始化 |
| 名义控制器 | 自适应导纳＋摩擦前馈 | 相同 |

两个 actor 的第零回合确定性动作都应严格为零。开始学习后，两种模型都允许更新所有
actor 参数。BC 导出时被清零的输入列也恢复梯度，从而把对照限制在初始化这一项改动上。
这不保证 BC 表示适合 RL；观测中的名义力也会随控制器基底改变。

## 这次比较固定训练预算下的最终策略

每个种子只尝试 32 个训练回合，继续使用原来的 16 个训练 case。三个种子为
`11、29、47`，每四回合更新一次。PPO 的损失、变步长 GAE 和 KL 停止处理沿用
[首轮训练实现](surface_learning_pilot.md#ppo-怎样更新残差)。

检查点 `0、16、32` 都保留，但这次只比较第 32 回合的策略。不能在看过成绩后退回
第 16 回合，再把它称作相同最终训练预算下的收益。原始从零开始版本也使用其第 32
回合权重，不能拿先前验证选中的不同回合来混合比较。

比较分两步看。先检查三个种子是否都满足原来的安全与跟踪门槛，再逐种子计算：

```text
paired_delta = mean_tangent_RMSE(BC_hidden_PPO, validation)
             - mean_tangent_RMSE(fresh_PPO_ep32, validation)
```

只有三个差值都为负，且三个种子均没有失败训练回合，才接受表示迁移作为
本轮优选初始化。没有一致改善时，保留从零开始版本。这个小预算试验无法回答 RL
是否已经收敛，也不能证明更长训练一定有用或无用。

全部验证结果和候选哈希固定后，再记录开发测试。开发 case 已经公开使用过，重复运行
相同配置和仿真种子不会增加独立场景数，也不构成新的盲测。

若某个验证回合没有有效的切向误差，该回合仍保留在报告中，配对平均值记为不可用。
不会剔除失败回合后重新计算“更好的平均值”。验证不合格时保存 `VALIDATION_VETO`，
不继续打开本轮开发测试。

## 相同种子不等于相同采样轨迹

两种训练使用相同 case 顺序、reset 种子和初始探索随机数种子。原实现的动作探索与
minibatch 打乱共用一个 PyTorch 随机数生成器。不同策略可能在不同更新轮数达到
KL 停止阈值，消耗的随机数数量随之改变；后续探索样本就未必一一相同。

这里保留原实现以便对照历史结果，并记录这个限制。可以声称配对了 case 和仿真噪声
种子，不能声称整个训练过程使用了完全相同的探索扰动。

## 训练与验证结果

三个迁移种子均完成了 32 个回合、8 轮采样更新和 192,000 个物理步，没有失败训练回合。
合计新增 96 个训练回合、576,000 个物理步。历史 fresh PPO 的训练记录直接复用，
不把它重复记为这轮新采集的数据。

这里固定的是采样回合预算及每轮允许的优化次数上限。KL 停止会让实际 minibatch
更新次数不同，因此不能声称两种初始化使用了完全相同数量的梯度更新。

三个迁移模型均通过四个验证任务的安全与跟踪门槛。以下为每个种子在相同四个 case
上的平均切向 RMSE，差值按“迁移减去 fresh”计算，负数才表示改善。

| 训练 seed | Fresh PPO，第 32 回合 / mm | BC 隐藏层 PPO，第 32 回合 / mm | 配对差值 / mm |
|---:|---:|---:|---:|
| 11 | 4.530 | 4.569 | +0.039 |
| 29 | 4.553 | 4.617 | +0.063 |
| 47 | 4.579 | 4.487 | −0.092 |

只有种子 47 改善，因此没有达到三个种子方向一致的接纳条件，按计划保留 `fresh_ep32`。
这些差值都不足 0.1 mm，且来自同两个验证物理任务组，不应当作统计显著的优劣结论。
本轮也没有依据结果追加训练回合或更换继承层。

固定上述比较以后，两组各运行了三个种子、四个开发 case，共 24 个回合，全部通过
原有安全与跟踪门槛，接触率均为 100%。开发测试不参与重新选型。

| 训练 seed | Fresh PPO / mm | BC 隐藏层 PPO / mm | 解析摩擦前馈 / mm |
|---:|---:|---:|---:|
| 11 | 2.467 | 2.408 | 2.403 |
| 29 | 2.470 | 2.488 | 2.403 |
| 47 | 2.406 | 2.435 | 2.403 |

开发测试中也只有一个种子的迁移策略降低了切向误差。三个迁移种子的平均切向误差都未
低于解析摩擦前馈。本轮不采用 BC 隐藏层初始化作为优选，项目仍保留经典控制强基线。
这说明本次表示迁移未显示稳定收益，不能推出所有预训练或更长预算的 RL 都无效。

逐 case 指标、训练曲线和冻结比较见[公开归档](../results/franka_surface_ppo_transfer/README.md)。

## 如何检查实现

代码见 [`train_surface_ppo_transfer.py`](../tools/train_surface_ppo_transfer.py)。
加载 BC 时会验证其自适应导纳契约、网络结构和受限 NumPy 执行器身份，只允许读取
数值权重。初始化记录保存了复制层的哈希，也保存了被排除的 BC 输出层身份。
检查保存的第零回合模型时，还会逐项比较它的两个隐藏层与已固定的 BC 候选。
仅验证输出为零不够，因为随机隐藏层配上零输出层也能通过这种检查。

测试使用非零 BC 权重检查隐藏层确实被复制，比较迁移前后价值网络逐位相同，并验证
零输出层没有被原来的补偿动作覆盖。失败路径需要保留已经产生的回合与异常信息，
不能只留下一个成功退出的空目录。

所有策略仅用于仿真。命令被限幅并不代表真实接触力天然有界，评价仍需检查原始力、
穿透及实际速度。

## 复现顺序

先完成[首轮学习试验](surface_learning_pilot.md#本地复现)和
[BC 输入消融](bc_closed_loop_transfer.md#复现入口)，保留两轮冻结命令输出的 SHA。
下面的三个大写 SHA 占位符应替换为各次冻结命令的真实输出，不是任意实验标签。

```bash
python -m tools.surface_ppo_transfer freeze \
  --parent dist/surface-learning-pilot-v1 \
  --bc-transfer dist/surface-bc-transfer-v1 \
  --dataset dist/surface-preparation-v2/dataset \
  --benchmark dist/surface-preparation-v2/benchmark \
  --output dist/surface-ppo-transfer-v1 \
  --expected-parent-plan-sha256 PARENT_PLAN_SHA \
  --expected-bc-plan-sha256 BC_TRANSFER_PLAN_SHA

python -m tools.surface_ppo_transfer run \
  --parent dist/surface-learning-pilot-v1 \
  --bc-transfer dist/surface-bc-transfer-v1 \
  --dataset dist/surface-preparation-v2/dataset \
  --benchmark dist/surface-preparation-v2/benchmark \
  --output dist/surface-ppo-transfer-v1 \
  --expected-plan-sha256 PPO_TRANSFER_PLAN_SHA
```

冻结步骤会核对 BC 已完成、三个选中模型均通过门槛，以及历史 PPO 对照的最终检查点。
`train` 和 `validate` 子命令配合 `--seed` 可分开执行，便于并行运行；后续 `run` 只复用
验证身份通过的完整产物。源码、预算、数据或已有比较发生变化时，应先排查，不能覆盖
旧目录继续计算。

本轮训练前保存的计划 SHA 为
`b921c97be68f89b8dc872c7b7f213c719050b839c79b2130e68089804c0f8bfa`。
它绑定当前源码及输入文件身份。更换环境或修改源码后重新冻结会得到不同 SHA，不能
把新运行的哈希冒充为本轮身份。

公开副本包含三个迁移种子的 `0/16/32` 权重、三个历史 PPO 最终权重、所继承的 BC
模型、全部训练曲线及评估报告。另附每组首种子、首开发 case 的完整物理轨迹，其余
原始轨迹保留在本地。无需 PyTorch 即可检查公开文件哈希、重算比较、核对初始隐藏层，
并从两份代表轨迹重新计算物理指标：

```bash
python -m tools.publish_surface_ppo_transfer --audit results/franka_surface_ppo_transfer
```

该检查不重新运行动力学，也不代表未分发的全部原始轨迹已由读者独立复核。

离线复核允许审计机器的 Python 或数值库版本与训练机器不同，但仍核对源码身份、
已记录的运行环境、有限数值权重及策略契约。实际加载策略重新运行仿真时，完整环境
身份检查仍然生效；离线复核通过不等于已经在新环境中重现动力学结果。

归档 manifest 的 `publisher_sha256` 记录生成归档时的程序版本。后续修复只读复核器
不会改写这个历史值，也不会重新计算训练或评估成绩。
