# 换向时的姿态代价：一次配对增益对照

在线切向补偿减少了擦拭位置误差，反向加速时却带来额外姿态误差。
本轮只调整常量姿态阻抗：四种方法都使用相同的新刚度与阻尼，重新运行原来的
10 工况 × 2 噪声种子 × 4 方法。法向控力、平移增益和 6 N 补偿上限保持不变。

在线方法的阶段检查从 40/42 提升到 42/42。姿态改善有代价：20 次运行的平均切向
RMSE 从 2.559 增至 2.575 mm，单次最大增加 0.051 mm。积分方法仍有两条阶段失败。

这是在公开失败案例上选参数后的开发对照。默认配置仍为原来的增益，不能把这轮
结果当作新 holdout，也没有给 BC/PPO 更换名义控制器或重新训练策略。

## 原来失败在哪里

[旧阶段表](../results/franka_online_compensation_errors/phase_metrics.csv)中，停顿换向工况
的 7–8 s 是反向加速段。两个种子的在线姿态 RMSE 相对无补偿基线都增加约 0.137°，
超过原有的 0.1° 门槛。固定前馈也增加约 0.118°。全程平均数没有暴露这两条失败。

完整日志中的力矩投影比例为 1，没有执行器裁剪。因而这次不能先把原因归到力矩饱和。
姿态误差主要出现在工具绕表面法向旋转的分量，也不符合“只有接触点偏置力矩”的解释。

### 两条没有采用的改动

先在 seed 11 的停顿换向工况做局部诊断，没有改接触模型或评价窗口。

| 探针 | 观察到的现象 | 为什么没有作为本轮修正 |
|---|---|---|
| 给切向补偿增加球形工具半径对应的力矩，另检查反号 | 几何预期方向使姿态误差更大；反号只小幅改善反向段，全程姿态变差 | 未支持“补上力臂力矩就能解决”的假设 |
| 用质量矩阵构造力矩零空间投影，替换原来的运动学投影 | 无补偿和在线方法的姿态误差都下降；配对差值仍约 0.137° | 共同改善没有消除补偿的相对代价，仍过不了同一个门槛 |

这两项是本地探索，未分发完整探针轨迹，不纳入下面的正式归档结论。
当前源码仍使用原来的零空间处理，也没有加入额外力臂补偿。

配对检查很重要：如果用改过零空间的在线控制器去比较没改过的旧基线，
会把两种不同修改混到一起。这种比较无法说明切向补偿自身的代价是否降低。

## 实际实现：只改姿态阻抗的常量预设

旋转控制沿用现有的旋转误差和角速度误差反馈：

$$
\tau_R=K_R e_R+D_R(\omega_d-\omega).
$$

`rotation_gain_scale = s` 对三个旋转轴做相同缩放：

$$
K_R(s)=sK_R(1),\qquad D_R(s)=\sqrt{s}\,D_R(1).
$$

原配置为每轴 $K_R=20$ N·m/rad、 $D_R=5$ N·m·s/rad。
本轮固定 $s=2$，变为 40 与 $5\sqrt{2}\approx7.071$。平移刚度没有一起翻倍。
该比例在控制器创建时确定，运行过程中不切换，和已有法向自适应增益调度是两回事。

平方根比例的动机可以从单轴小误差近似看出来：

$$
I\ddot e+D_R\dot e+K_R e=0,\qquad
\zeta=\frac{D_R}{2\sqrt{IK_R}}.
$$

假定等效惯量 $I$ 不变，同步乘 $s$ 和 $\sqrt{s}$ 可以保持这个简化模型的阻尼比。
七轴机械臂的任务空间惯量随姿态变化，接触也会耦合各轴；这里没有声称达到临界阻尼，
更没有从这条近似式推出全机器人接触稳定性。

选择之前另试过仅增刚度、仅增阻尼。两项一起调整在诊断工况中的姿态误差更低，
随后固定 $s=2$，所有方法使用同一比例运行完整对照；没有根据完整结果继续搜索比例。

```python
controller = SurfaceAdaptiveController(
    frame, tangential_mode="online", rotation_gain_scale=2.0,
)
```

实现入口是 [`SurfaceAdaptiveController`](../src/compliant_control_lab/surface_control.py)。
传入自定义 `base` 时，应直接配置这个 base 的旋转增益，不能再用该参数覆盖它。

## 完整对照与代价

[新全程结果](../results/franka_rotation_gain_comparison/comparison.csv)有 80 行，
[新阶段表](../results/franka_rotation_gain_comparison/phase_metrics.csv)有 168 行。
扰动时序和种子均沿用旧实验，四种方法都使用 $s=2$，原有门槛没有调整。

| 方法 | 原 $s=1$ 阶段通过 | 新 $s=2$ 阶段通过 | 新全程检查通过 |
|---|---:|---:|---:|
| 无切向补偿 | 42/42 | 42/42 | 20/20 |
| 有界切向积分 | 34/42 | 40/42 | 20/20 |
| 固定摩擦前馈 | 40/42 | 42/42 | 20/20 |
| 在线等效负载补偿 | 40/42 | 42/42 | 20/20 |

在线方法在 7–8 s 反向加速段的姿态 RMSE，seed 11/29 分别为 0.2346° / 0.2354°。
同增益的无补偿基线为 0.1474° / 0.1481°，配对增量为 0.08723° / 0.08731°，
均低于原来的 0.1°。积分方法在同一段仍增加 0.12350° / 0.12333°，两条失败没有删掉。

下面直接比较在线方法自身的新旧配置。每个数值是 10 工况 × 2 种子的全程 RMSE 均值，
并非把所有采样点拼接后重算的 RMSE，也不与原 24-case、4.5 秒回归混用。

| 在线方法指标 | 原 $s=1$ | 新 $s=2$ |
|---|---:|---:|
| 姿态 RMSE 均值 [°] | 0.3821 | 0.2030 |
| 切向 RMSE 均值 [mm] | 2.5588 | 2.5746 |
| 法向力 RMSE 均值 [N] | 0.2814 | 0.2839 |

逐 case/seed 比较，姿态误差在全部 20 次运行下降；切向 RMSE 的最大增加为 0.05091 mm，
法向力 RMSE 的最大增加为 0.006454 N。与同为 $s=2$ 的固定前馈相比，在线方法仍在
20 次配对中全部降低切向 RMSE。因此选择保留这项可选预设，但不声称所有指标都改善。

切向退化在短窗口里更明显：反向加速 seed 11 的阶段 RMSE 增加 0.11766 mm。
切向速度误差 RMS 在全部 20 次全程统计中增加，均值增加 3.71%。这两项代价也是暂不
改默认值的原因；不能只报姿态门槛通过，就认为换向跟踪已经没有问题。

四份预选完整轨迹用新增益通过了 Python/C++ 逐步核验，共 24,000 步。
最大 wrench 分量差为 `4.4408920985e-15`，最大关节力矩差为 `3.5527136788e-15`；
Python 重算与保存命令的最大差为 0。
[回放报告](../results/franka_rotation_gain_cpp_replay/report.json)保留每份轨迹的检查结果。
其中附带的耗时 benchmark 仍是原默认配置的独立数值基准，不能当作新增益闭环或硬件实时测试。

## 怎样复核

安装开发依赖后，在仓库根目录运行。仿真输出目录必须尚不存在：

```bash
python -m compliant_control_lab.online_compensation_experiment \
  --rotation-gain-scale 2 --output /tmp/rotation-gain-rerun

python -m tools.audit_online_compensation_errors \
  --audit /tmp/rotation-gain-rerun

# 只读核对仓库中的新归档
python -m tools.audit_online_compensation_errors \
  --audit results/franka_rotation_gain_comparison
```

比例同时写入 `protocol.json`、`configurations.json` 和 `manifest.json`。
四种方法的实际刚度、阻尼也写入配置，不能只改一行实验标签。四份预选完整轨迹另带
标量 `rotation_gain_scale`，Python 与 C++ 回放都读取它；旧轨迹没有该字段时按 1 处理。
紧凑轨迹仍保留原来的精确字段集合，避免把控制器配置混入按时间采样的数组。

审计会拒绝各文件比例不一致、声明的旋转增益不符或完整轨迹比例不符的归档。
历史实验的源码哈希与当前源码不同，会报告 `current_source_matches_archive: false`，
同时要求来源快照匹配审计器中固定的已知历史摘要；陌生的来源快照仍会拒绝。
不会仅凭实验目录自带的 `COMPLETE` 文件信任重封后的来源声明。
归档哈希和逐轨迹指标也仍须通过检查。这确认了已知来源声明和产物的一致性，
不构成对仿真执行过程的外部认证。
运行过程中源码发生变化则仍然拒绝发布结果，这条保护没有取消。

## 还需要检查的范围

这轮只覆盖原误差实验的 case 16 几何配置。两个噪声种子不能替代不同姿态、工具质量
或表面方向；原有 24-case 回归仍对应 $s=1$。因此暂不把 $s=2$ 改为全仓库默认值。
更大的姿态刚度还可能缩小力矩余量，当前仿真通过不能推成硬件安全结论。

原来的高摩擦问题也没有因此消失：请求最大约 5.984 N，接近配置中的 6 N 上限，
但未触发本协议定义的 `compensation_limit_observed` 标志，不能写成已经发生硬裁剪。
后续应先检查新增益在原 24-case 网格的代价，再讨论是否值得引入更多控制项。
