# 8 N 的速度代价集中在评估区间的第一个半秒

[8 N 补偿预算](budget_transfer.md)在原 public24 网格上有 25/48 组因切向速度代价记为 FAIL。
这一页把已经测得的代价按时间和方向拆开。48 对轨迹全部取自已有的 96 条归档轨迹，
新增仿真次数为 0。控制律与默认的 6 N、姿态增益 `s=1` 保持不变，原兼容性结论也保留。

## 结论

**平均净速度代价主要集中在 1.5–2.0 s，全段增量由沿轨迹分量主导。**
48 对是原 24 个 case 在两个姿态增益下的配对结果：

- 切向速度误差的总 MSE 与沿向 MSE 在 48 对中全部增加，横向 MSE 全部减少，
  均值分别为 +2.08636、+2.37285、−0.28649 $(\mathrm{mm/s})^2$。
- 1.5–2.0 s 的贡献为均值净增量的 84.89%（25 组 FAIL 内为 87.47%）。
- 最后两个窗口在 48 对里全部为负贡献：8 N 的窗口速度 MSE 更低，但不能据此断言窗内每个采样都更好。

表中每个数是加权窗口贡献 $(N_w/N)\,\Delta\mathrm{MSE}_w$，单位 $(\mathrm{mm/s})^2$，
六个数相加等于该组整段的 $\Delta\mathrm{MSE}$。

| 窗口 (s) | 48 对均值 | 25 FAIL 均值 | 正/负对数（48 对） | case 23、`s=2` |
|---|---:|---:|---:|---:|
| 1.5–2.0 | +1.77112 | +2.34668 | 48/0 | +3.19847 |
| 2.0–2.5 | +0.10864 | +0.10026 | 32/16 | −0.01778 |
| 2.5–3.0 | +0.33408 | +0.33693 | 48/0 | +0.34101 |
| 3.0–3.5 | +0.18569 | +0.17268 | 48/0 | +0.11000 |
| 3.5–4.0 | −0.08909 | −0.06886 | 0/48 | −0.03714 |
| 4.0–4.5 | −0.22408 | −0.20496 | 0/48 | −0.11891 |

case 23、`s=2` 是速度代价最坏的一组，整段切向速度误差 RMS 由 4.69115 升至 5.04802 mm/s。
它第二个窗口的贡献为负，说明“每个窗口都变差”并不成立。边界例 case 7、`s=1` 的整段 RMS
增量为 +0.200101 mm/s，按未改动的 +0.2 mm/s 判据仍是 FAIL。

84.89% 的分母是均值净总 MSE 增量 2.08636 $(\mathrm{mm/s})^2$。
这是一项有符号贡献的比例，负贡献会抵消正贡献，所以个别贡献比例也可能大于 100%。
它不表示 RMS 的增幅，也不表示有多少 case 在这个窗口失效。

## 怎么拆的

评估区间 $[1.5, 4.5)$ 等分为六个左闭右开的 0.5 s 窗口，每窗 250 个采样，共 1500 个，
控制周期 2 ms。逐采样坐标系由两臂共有的目标速度给出：$n$ 是真实表面法向，
$\hat t_\parallel$ 是目标速度投影到切平面后归一化的方向，$\hat t_\perp = n \times \hat t_\parallel$。
误差一律取实际减目标，两臂用同一组坐标系打分。评估段内目标切速始终不为零；目标静止时
切向方向无定义，分析器直接报错，不做兜底。

分解使用两个恒等式：

$$
\mathrm{MSE} = \mathrm{MSE}_\parallel + \mathrm{MSE}_\perp,
\qquad
\Delta\mathrm{MSE} = \sum_{w=1}^{6} \frac{N_w}{N}\,\Delta\mathrm{MSE}_w .
$$

第一个成立是因为 $(\hat t_\parallel, \hat t_\perp)$ 是切平面的正交基；第二个只依赖六个窗口互不重叠、
覆盖整段且 $\sum_w N_w = N$。RMS 差值不能这样跨窗口平均或相加。
上表使用 MSE 贡献，整段 RMS 差值仍按原公式计算；CSV 同时保留各窗口的 RMS 供查看。

每个方向另外记录了均值与总体方差，满足 $\mathrm{MSE} = \bar e^2 + \operatorname{Var}(e)$
（$\mathrm{ddof}=0$）。这只是在移动的沿向／横向坐标里的描述性拆分：方差大不等于振荡或
测量噪声，本页不这样解释它。

## 这些数字不能读成什么

- “第一个半秒”指评估区间的开头。接触和切向目标运动都在 1.5 s 之前开始，
  因而不能把 1.5–2.0 s 当作首次接触瞬态。
- 误差相对同一时刻目标计算；本页没有计算到目标路径最近点的几何偏差。
- 48 对的补偿请求首次出现差异落在 1.656–1.794 s，位置和速度在其后一个采样（2 ms）
  才出现差异。这与同一记录行内状态 $x[k]$ 先于命令 $u[k]$ 的约定一致。
  这个间隔不能解释为测得的控制延迟，也不能证明某个内部环节导致了速度代价。
- 精简归档没有保存本周期限幅、更新就绪、变化速率限制和校正后滤波法向力，
  不能据补偿向量范数反推这些量。
- 提高上限本身是受控对照，但同一条轨迹内部的相关不能识别中介变量。因此不能得出
  “8 N 在整段持续过推”，也不能只凭这一页给补偿加泄漏项。
- 没有硬件、无源性或跨工况推广的证据。

## 复现与只读审计

在仓库根目录执行，两条命令都不重新积分动力学：

```bash
# 只读已有归档，并从父轨迹重算全部统计
python -m tools.velocity_cost_study --audit results/franka_velocity_cost

# 重新生成派生归档；输出目录必须不存在，重复运行需换目录名
python -m tools.velocity_cost_study --output /tmp/compliant-control-velocity-cost-01
```

第一条审计命令预期输出含 `audit_status=PASS`、`pairs=48`、`windows=288`、`new_simulations=0`、
`original_compatibility_passed=23`。审计通过表示派生统计与固定输入一致，25 组兼容性 FAIL 仍然保留。
第二条命令输出新目录路径。

[研究工具](../tools/velocity_cost_study.py)固定两份父归档的 manifest，并记录派生工具及依赖源码哈希，
核对 96 条轨迹的身份、路径和 `row_origin`，并要求配对速度 RMS 差值重算出父筛查里的
同一个值。它还绕开[配对分析器](../tools/velocity_cost_analysis.py)的辅助函数独立复算一遍：
用时间掩码重建切向误差 MSE，逐行检查沿向＋横向是否闭合、均值²＋方差是否闭合、
六个加权贡献之和是否等于整段差值，以及请求首次差异之前两条轨迹的共有数组是否逐元素相同。

归档包含 [48 行整段结果](../results/franka_velocity_cost/pairs.csv)、
[288 行窗口结果](../results/franka_velocity_cost/windows.csv)与
[首次差异时间](../results/franka_velocity_cost/timing.csv)。
[协议](../results/franka_velocity_cost/protocol.json)记录评估约定，
[摘要](../results/franka_velocity_cost/summary.json)提供分组统计。
想自己核对 84.89%：把 `windows.csv` 按 `start_s` 分组求 `weighted_mse_delta_m2_s2` 均值，
除以 `summary.json` 中的 `groups.all.mean_mse_delta_m2_s2`；表里的单位是 $\mathrm{m^2/s^2}$，
乘 $10^6$ 换成 $(\mathrm{mm/s})^2$。

下一步只做少量精确重放，在 1.5–2.0 s 附近加装观测量，检查补偿系数的增长、变化速率限制
与更新就绪情况，再根据观测决定是否改变更新律。失效判据不因这页结果改动。
